# Protocols

How I like a console set up. These are preferences with reasons, written so that someone
else at the desk (or a future me at 2 a.m.) can follow them, and so that one day the site
can hold a `.ses` up against them and say where it differs.

Each page follows [`templates/protocol.md`](../templates/protocol.md). They are stubs until
written; the headings mark what needs deciding.

| Page | Topic | State |
|------|-------|-------|
| [`naming.md`](naming.md) | Channel, bus, snapshot and macro naming | To write |
| [`fader-banks.md`](fader-banks.md) | Bank layout, what sits on which layer, spill sets | To write |
| [`snapshots.md`](snapshots.md) | Snapshot scope, safes, recall order, cue numbering | To write |
| [`macros.md`](macros.md) | What gets a macro, colours, placement | To write |
| [`patching.md`](patching.md) | Socket naming, rack ordering, record outputs | To write |
| [`housekeeping.md`](housekeeping.md) | Saving, versioning, hand-over, what travels with the show | To write |

Protocols describe my setup, not DiGiCo behaviour. A fact about what the console does belongs
in `format/` or `inbox/`, tagged.
